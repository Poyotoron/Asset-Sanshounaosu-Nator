# 参照を検査する

検査は**読むだけの操作**です。Prefab は書き換わりません。

## 対象を指定する

指定の方法は 3 つあります。どれでも結果は同じです。

| 方法 | 操作 |
|---|---|
| 選択中を使う | Project ウィンドウで選んでから「**選択中を使用**」を押す |
| ドラッグ＆ドロップ | 「対象 Prefab / フォルダ」欄へ放り込む |
| フォルダを指定 | フォルダを指定すると、**その配下の Prefab をすべて**対象にする |

指定できるのは `.prefab` とフォルダです。Prefab が 1 つも見つからない場合は「指定対象に Prefab がありません。」と表示されます。

- 対象が **1 件**なら、単体の検査結果が出ます。
- 対象が **2 件以上**なら、確認ダイアログを経て[まとめて検査](batch.md)になります。

## 検査する

「**参照を検査**」を押します。走査中は進捗が表示されます。

### 親 Prefab と入れ子の Prefab も辿ります

検査は、指定した Prefab だけを見て終わりません。**Prefab Variant の親**や、**中に入れ子になっている Prefab** を辿って、そこも検査します。

これは「開いている Prefab 自体は無事なのに、親が壊れているせいで表示が崩れる」というケースを取りこぼさないためです。結果に、指定していないファイルのパスが出てくることがありますが、正常な動作です。

### 何を見ているのか

Prefab のテキストを 1 行ずつ読み、参照を書いている箇所をすべて拾います。具体的には次の 3 種類です。

| 種類 | どこに出るか |
|---|---|
| 通常の参照 | コンポーネントのフィールド（Mesh、Material、Transform など） |
| **override の参照** | Prefab インスタンスの変更差分。ここが漏れると「直したのに直らない」が起きます |
| 親 Prefab の参照 | Prefab Variant / 入れ子の参照元 |
| スクリプトの参照 | コンポーネントの実体を指す参照。ここが壊れると Missing Script になります |

## 検査対象のファイル自体が無い場合

指定した Prefab のファイル本体が存在しないと、専用の表示になります。

```
検査対象のファイル本体が見つかりません: Assets/...
```

このときは中身を読めないので、代わりに「**同名候補を探す**」が使えます。元のファイル名から、同名・類似の Prefab をプロジェクト内で探して提示します。

!!! warning "ここで出る候補はすべて推測です"
    自動で差し替えることはしません。候補を見て、**自分で対象を選び直す**ための手がかりとして使ってください。

## 検査するとログが 1 件出ます

検査を実行するたびに、プロジェクト直下へ記録が書き出されます。

```
AssetSanshounaosuNator_Backup/<日時>/inspection.md
```

まとめて検査した場合は `batch-inspection.md` です。**検査しかしていなくてもフォルダは増えます。** 中身の説明と掃除の考え方は[バックアップとログ](backup.md)にあります。

## 検査が終わったら

結果の読み方は[結果の読み方](results.md)へ進んでください。
