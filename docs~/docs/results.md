# 結果の読み方

## サマリと深刻度

結果の先頭には、Error と Warning の件数、種別ごとの件数、欠落している Prefab の数が並びます。

| 記号 | 深刻度 | 意味 |
|---|---|---|
| `●`（赤） | **Error** | 参照先を解決できていません。ほぼ確実に壊れています |
| `▲`（黄） | **Warning** | 壊れている可能性はありますが、**誤検知や、Unity 側で吸収されるものを含みます** |

Warning を全部直そうとしないでください。特に空参照（後述）は、正常な未設定を大量に含みます。

## 5 つの分類

結果の各項目には、次のどれかのラベルが付きます。フィルタのボタンにも同じラベルが並んでいて、押すと表示を絞り込めます。ボタンにマウスを乗せると説明が出ます。

### T-A GUID 解決不可

参照が指している GUID が、**プロジェクト内のどこにも存在しません。**

- パッケージが未導入（Modular Avatar、VRCFury、lilToon、Poiyomi など）
- `.meta` が再生成されて GUID が変わった
- アセットを削除した、または別プロジェクトから持ってきた

いちばん多く、いちばん「直せる見込みがある」分類です。3 つの探索モードすべてが対象になります。

### T-B fileID 解決不可

GUID は解決するのに、その**中の特定のオブジェクトが見つからない**状態です。FBX を再インポートしてサブアセット（Mesh、AnimationClip など）の構成が変わったときに起きます。

このラベルには 2 つの状態があり、深刻度が変わります。

| 状態 | 表示 | 深刻度 |
|---|---|---|
| ファイルはあるが、その中の fileID が無い | `T-B fileID 解決不可` | **Warning**（Unity 側で吸収されることがあります） |
| **ファイル本体が存在しない** | `T-B 参照先ファイル本体欠落` | **Error** |

後者は要注意です。Unity の内部キャッシュ上は GUID が解決できているのに、実ファイルが無い状態を指します。

### T-C Missing Script

コンポーネントの実体（スクリプト）を指す参照が解決できません。Inspector で `Missing (Mono Script)` になっているものです。

- Dynamic Bone → PhysBone のような移行で、元のスクリプトが無くなった
- スクリプトを含むパッケージを外した

### T-D 空参照（誤検知を含む）

参照が空（`fileID: 0`）の状態です。**既定では非表示**になっています。専用のボタンで表示を切り替えます。

!!! warning "これは大半が正常です"
    「まだ何も入れていないフィールド」も同じ形で記録されます。**誤検知を多く含むため、既定でオフにしてあります。** 他に手がかりが無いときだけ覗いてください。

### T-E 型不一致

参照は解決できたものの、**取り出したアセットの型がフィールドの期待と違います。** 手作業で GUID を書き換えて失敗した場合などに出ます。

## 「欠落 Prefab」のまとめ表示

Prefab が丸ごと見つからない場合、その 1 つの欠落が**数十件の参照エラー**として現れます。全部を個別に並べても読めないので、**GUID ごとにまとめて**表示します。

```
Prefab 欠落: Hoodie  (37 件)
```

展開すると、次の情報が出ます。

| 表示 | 意味 |
|---|---|
| `guid:` | 壊れた参照が指している GUID。**これがすべての手がかりの起点です** |
| 対象ファイル | どの Prefab の中の話か |
| 内訳 | 親 Prefab としての参照 / override の参照 / 通常の参照の件数 |
| 元パス | 分かる場合、元々あった場所 |

名前が分からない場合は「Prefab 欠落: 名前不明」と出ます。手がかりが GUID しか無い状態です。この場合でも `.unitypackage` の索引やごみ箱から名前が判明することがあります。

!!! info "同じ GUID を他の Prefab も参照している場合"
    「同じ GUID は他の Prefab からも参照されています。この操作では書き換えません」という警告が出ます。**まとめて修復しても、書き換わるのは今見ているファイルだけです。** 他のファイルは 1 つずつ検査・修復してください。

## 個別の項目を開く

各項目を開くと、次が表示されます。

- `guid:` と `fileID:` — 壊れた参照そのものの値
- ファイル名と**行番号** — テキストエディタで直接見たいときに使えます
- 「**対象を表示**」 — Prefab を開いて、該当する GameObject を選択します
- 「**候補を探す**」 — 候補パネルを開きます（[プロジェクト内](search-project.md) / [.unitypackage](search-unitypackage.md) / [ごみ箱](search-trash.md)）

「欠落 Prefab」のまとめの下に並ぶ項目には「候補を探す」がありません。**まとめて修復する方が確実なので、グループ側の操作に一本化しています。**

## 結果を持ち出す

「**結果を Markdown でコピー**」を押すと、表形式でクリップボードにコピーされます。不具合を報告するときや、あとで見返すときに使ってください。

!!! tip "共有する前に確認してください"
    出力にはアセットのパスと名前が含まれます。購入したアセットの名前が入るので、公開の場に貼るときは中身を確認してください。
