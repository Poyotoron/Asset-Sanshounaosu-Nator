# 候補を探す：.unitypackage

BOOTH などで買った `.unitypackage` を置いてあるフォルダを登録しておくと、**壊れた GUID がどの `.unitypackage` に入っていたのかを特定**できます。このツールでいちばん強力なモードです。

探索設定の「**モード 2: .unitypackage の GUID 索引**」で有効・無効を切り替えられます。

## なぜ確実なのか

`.unitypackage` の中には、**アセットの GUID と、元のプロジェクトでのパス**がそのまま入っています。壊れた参照が持っている GUID と突き合わせれば、「この参照が指していたのは、この package のこのファイルだ」と**推測ではなく特定**できます。

## 索引を作る

使う前に一度だけ（そして買い足すたびに）索引を作ります。

1. 「**探索設定**」を開きます。
2. 「**フォルダを追加**」で、`.unitypackage` を置いているフォルダを選びます。複数登録できます。サブフォルダも辿ります。
3. 「**索引を構築 / 更新**」を押します。件数の確認ダイアログが出るので、続行します。

!!! warning "初回の索引構築は時間がかかります"
    `.unitypackage` は圧縮されたアーカイブです。中身を読むために全体を伸長する必要があるため、**対象が多いフォルダでは数分〜数十分かかることがあります。** 進捗バーが出て、途中でキャンセルできます。

    キャンセルしても、**そこまでに走査した分は保存されます。** 索引の状態は「未完了」と表示され、続きは次回の構築で埋まります。

2 回目以降は、**ファイルのサイズと更新日時が変わっていない `.unitypackage` はスキップ**します。買い足したぶんだけを追加で読むので、初回ほど時間はかかりません。

索引の状態は探索設定に表示されます。

```
.unitypackage 索引: 128 package / 96,432 GUID / 最終走査 2026-08-16T…
```

!!! info "索引は `Library/` の中にあります"
    `Library/AssetSanshounaosuNator/unitypackage-index.json` に保存されます。`Library/` を消すと索引も消えますが、**登録したフォルダの設定は残る**ので、「索引を構築 / 更新」を押し直せば作り直せます。

## 2 種類の見つかり方

このモードの候補には、性質のまったく違う 2 つがあります。**混同しないでください。**

### GUID 一致（確実な復元）

壊れた参照の GUID が、索引の中に見つかった場合です。

```
確実な復元 / .unitypackage / GUID 完全一致
```

その `.unitypackage` の中に、**まさにその参照が指していたアセットが入っています。**

### 名前一致（推測）

GUID が索引に無かった場合、代わりに**名前で**探します。GUID が作り直されてしまったケース（`.meta` の再生成など）を拾うためです。

```
推測 / .unitypackage / 部分一致「Hoodie」
```

!!! warning "名前一致は、インポートしても直りません"
    名前が同じでも GUID が違うので、**その package を入れただけでは参照は繋がりません。** インポートしたあと、**再検査して[プロジェクト内の候補](search-project.md)として選び直す**という 2 段階が必要です。

    ありふれた名前（多数の package や GUID に一致する名前）は、ノイズになるので候補から自動的に除外されます。提示数にも上限があります。

## インポートは自分で行ってください

!!! danger "このツールは `.unitypackage` を自動でインポートしません"
    インポートは、プロジェクトに何が追加され、何が上書きされるかが package の中身次第で変わる操作です。**影響範囲をツール側で予測できない**ため、実行しません。

候補には package のファイル名とフルパスが表示され、次の操作ができます。

| ボタン | 動作 |
|---|---|
| **場所** | エクスプローラー（Finder）でその `.unitypackage` の場所を開く |
| **コピー** | パスをクリップボードへコピーする |

自分でインポートしたあと、**もう一度「参照を検査」してください。** GUID 一致の package だった場合は、インポートした時点で参照が復活していることがあります。

## 索引が使えるのはこのモードだけではありません

索引に記録された「元のパス」は、**名前の手がかり**としても使われます。GUID しか分からず「名前不明」だった欠落 Prefab の名前が、索引のおかげで判明することがあります。その名前は[プロジェクト内探索](search-project.md)にも自動で渡されます。
