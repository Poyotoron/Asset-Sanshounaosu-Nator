# クイックスタート

壊れた Prefab を 1 つ選んで、原因を突き止めるところまでを最短でやります。**このページの手順だけでは何も書き換わりません。** 書き換えが起きるのは、最後の[修復する](repair.md)へ進んだときだけです。

## 1. 準備を確認する

メニュー `Tools > 参照直すネーター` を開きます。初回は確認ダイアログが出るので、内容を読んで「了承して開く」を押します。

赤い警告が出て「参照を検査」ボタンが押せない場合、プロジェクトが Force Text になっていません。先に[事前準備（Force Text）](serialization.md)を済ませてください。

!!! tip "先にプロジェクトをコミット / バックアップしておく"
    このツールは修復のたびに自動でバックアップを取りますが、**修復前の状態が Git などに残っている方が確実に安全です。**

## 2. 壊れた Prefab を指定する

Project ウィンドウで対象の `.prefab` を選び、ツールの「**選択中を使用**」を押します。ウィンドウの「対象 Prefab / フォルダ」欄へドラッグ＆ドロップしても構いません。

- **フォルダを指定すると、その配下の Prefab がすべて対象**になります。
- 複数選択もできます。2 件以上を指定すると[まとめて検査](batch.md)になります。

まずは 1 件だけで試すのがおすすめです。

## 3. 検査する

「**参照を検査**」を押します。数秒で結果が出ます。

このとき、Prefab Variant の親や、中に入れ子になっている Prefab も**自動的に辿って**検査します。「この Prefab 自体は無事だが、親が壊れている」というケースを取りこぼさないためです。

!!! info "検査は何も書き換えません"
    検査は読むだけです。ただし、**検査の記録はログとして 1 件書き出されます**（プロジェクト直下の `AssetSanshounaosuNator_Backup/` の中）。壊す操作ではありませんが、フォルダが増えていくことは知っておいてください。

## 4. 結果を読む

問題が無ければ「問題ありません」と表示されます。問題があれば、上部に件数のサマリが出て、下に一覧が並びます。

- 赤い `●` が **Error**（ほぼ確実に壊れている）
- 黄色い `▲` が **Warning**（誤検知を含む、または Unity 側で吸収され得る）

Prefab が丸ごと欠落している場合は、**「欠落 Prefab」**という見出しでまとめて表示されます。1 つの Prefab の欠落が数十件の参照エラーとして現れるのが普通なので、名前ごとにまとめてあります。

分類の意味は[結果の読み方](results.md)にあります。

## 5. 候補を探す

直したい項目を開いて「**候補を探す**」を押します。候補パネルが開き、見つかったものが並びます。

各候補には必ず **「確実な復元」** か **「推測」** が付いています。ここを読み飛ばさないでください。

- 候補が 0 件のときは、`.unitypackage` の索引を作る、ごみ箱を走査する、といった手が残っています。[困ったときは](troubleshooting.md)を参照してください。

## 6. 直す

候補の内容に納得できたら「**選択して修復**」を押します。

1. 対象ファイルがバックアップフォルダへコピーされ、
2. 書き換え内容の確認ダイアログ（YAML を直接書き換える場合は Diff）が出て、
3. あなたが承認したときだけ書き換えが実行され、
4. 再インポートと再検査が自動で走ります。

!!! danger "承認する前に必ず読んでください"
    ダイアログには、候補が推測かどうか、バックアップの保存先、書き換わる行がそのまま表示されます。**ここが最後の分岐点です。** 詳細は[修復する](repair.md)へ。
