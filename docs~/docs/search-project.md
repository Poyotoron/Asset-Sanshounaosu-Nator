# 候補を探す：プロジェクト内

3 つの探索モードのうち、**いちばん手軽で、いちばん推測の色が濃い**モードです。「候補を探す」を押すと、他のモードと一緒に自動で走ります。事前準備は要りません。

探索設定の「**モード 1: プロジェクト内の類似候補**」で有効・無効を切り替えられます。

## 何をしているのか

壊れた参照から**名前の手がかり**を集め、プロジェクト内の同じ型のアセットと名前を突き合わせます。GUID は使いません（GUID で見つかるなら、そもそも壊れていません）。

手がかりには、次のものが使われます。上にあるものほど信頼できます。

| 手がかり | どこから来るか |
|---|---|
| `.unitypackage` 索引に記録された元のパス | 索引を作ってあれば使われます |
| ごみ箱で見つかった同じ GUID のファイル名 | ごみ箱を走査してあれば使われます |
| 参照先として記録されているパス・名前 | 壊れ方によっては残っています |
| 参照している GameObject の名前 | 最後の手段 |

!!! tip "他のモードを先に走らせると、このモードの精度が上がります"
    `.unitypackage` の索引やごみ箱の走査で**元の名前が判明する**と、それが手がかりとして加わります。「名前不明」で候補が出ないときは、先に[索引の構築](search-unitypackage.md)を試してください。

## 候補の見方

各候補には、判定の根拠がそのまま表示されます。

```
推測 / プロジェクト内 / score 800 ・ 前方一致「Hoodie_A」(ファイル名)
```

| 一致の種類 | 目安 | 意味 |
|---|---|---|
| 完全一致 | 最も高い | 名前がそのまま同じ |
| 拡張子違いの一致 / 前方一致 | 高い | 片方がもう片方で始まる |
| 部分一致 | 中 | どちらかがどちらかを含む |
| 編集距離 | 低い | 数文字違う。**当てにしすぎないでください** |

!!! danger "このモードの候補は、すべて推測です"
    名前が完全一致していても、**GUID が違う以上は別のファイル**です。同じ名前で中身の違うアセット（`Body`、`Material`、`Face` など）は珍しくありません。修復の前に、候補の中身を Inspector で確認してください。

- 候補は最大 8 件まで、名前として意味のある一致に満たないものは除外されます。
- 候補が並ぶ順は、**確実な候補が先、その中でスコア順**です。プロジェクト内の候補は常に推測なので、他のモードで確実な候補が出ていればそちらが上に来ます。

## 候補が読み込めない Prefab の場合

候補として出た Prefab 自身が壊れていて読み込めないことがあります。この場合は次のように表示され、修復ボタンが押せません。

> 名前は一致しますが、この Prefab 自身も読み込めません。先にこの Prefab の壊れた参照を修復してください。

**先にそちらを直してから**、元の Prefab に戻ってきてください。

## 手動で指定する

候補パネルのいちばん下に「**手動指定（推測）**」の欄があります。「これだ」と分かっているアセットがあるなら、ここへドラッグして「手動指定した候補で修復」を押せます。

- Missing Script の場合、この欄は MonoScript しか受け付けません。
- 手動で指定したものも**推測として扱われます。** バックアップと Diff の確認は同じように行われます。

## 探索の内訳を見る

候補パネルには、探索が何をしたかの内訳が表示されます。

```
プロジェクト内探索の手がかり: 『Hoodie』
プロジェクト内: 3 件
  t:Prefab等 812 件 → 実体なし 4 / 自分自身 1 / … → 条件一致 5 件中 3 件を提示
```

候補が 0 件のときは、ここを読むと理由が分かります。**手がかりが「なし」**なら、名前が一切分かっていないので、このモードでは原理的に何も出ません。他のモードへ進んでください。
